QUESTION: How does compaction interact with the UI, and is pre-compaction context preserved?

ANSWER:   Pre-compaction context is NOT preserved. Only the compaction summary marker 
          is visible in the UI, and the event is sent to the frontend but ignored.

                              CONCLUSION
═══════════════════════════════════════════════════════════════════════════════

The compaction algorithm itself is excellent and works reliably. However:

• Pre-compaction context is LOST immediately
• Frontend receives event but IGNORES it
• User sees compaction summary badge but NO feedback when it happens
• No way to see what was discarded or when
• No compaction history or timeline

This is by design - the system compresses context silently. To enable viewing
pre-compaction context, you need to:

1. Save old message data before discarding
2. Create a storage model for compaction events
3. Add frontend handlers and UI components
4. Build inspection/timeline UI

See COMPACTION_ANALYSIS.md for detailed implementation guide.
